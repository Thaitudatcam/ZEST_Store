# Kế hoạch: NotificationBell + AskAI Search + Messenger-style Chatbot

## Tổng quan & Phát hiện quan trọng
- **`ThongBao` entity + `ThongBaoRepository` ĐÃ CÓ SẴN** (chỉ thiếu Service/Controller/SSE)
- **`OpenAiService` + `ThongKeService` ĐÃ CÓ SẴN** → tái sử dụng cho ask-ai (không cần LLM mới)
- **SSE pattern** sẵn có (`OrderSseService`) → copy cho notifications
- Admin header hiện đang **trống hoàn toàn** → chèn 2 component vào

Phân chia thành **6 giai đoạn** (Backend 1-2, Frontend 3-5, Messenger 6):

---

## GIAI ĐOẠN 1 — Backend: Notifications (REST + SSE)

### 1.1 `service/ThongBaoService.java` (mới)
- `@Service @RequiredArgsConstructor`, inject `ThongBaoRepository`, `NotificationSseService`
- Methods:
  - `getByUser(maNguoiDung)` → `findByNguoiDung_MaNguoiDungOrderByNgayTaoDesc`
  - `countUnread(maNguoiDung)` → `countByNguoiDung_MaNguoiDungAndDaDocFalse`
  - `markAsRead(maThongBao, maNguoiDung)` + `markAllRead(maNguoiDung)`
  - `taoThongBao(maNguoiDung, tieuDe, noiDung, loai, lienKet)` — helper tạo + push SSE

### 1.2 `service/NotificationSseService.java` (mới — copy `OrderSseService`)
- Giống hệt `OrderSseService` nhưng **key = `maNguoiDung`** thay vì orderId
- `addEmitter(maNguoiDung)`, `sendNotification(maNguoiDung, payload)` với event name `"notification"`

### 1.3 `controller/ThongBaoController.java` (mới)
- `@RestController @RequestMapping("/api/notifications") @PreAuthorize("hasAnyRole('ADMIN','STAFF')")`
- `GET /` → list, `GET /unread-count` → `{count}`, `PUT /{id}/read`, `PUT /read-all`
- `GET /stream` (produces `TEXT_EVENT_STREAM_VALUE`) → SSE, resolve user từ auth (chỉ subscribe kênh của mình)

### 1.4 Wire notifications vào các service hiện có
Inject `ThongBaoService` vào các call site đã gọi `orderSseService.sendOrderStatusUpdate(...)`:
- `DonHangService` (cập nhật trạng thái đơn) → tạo thông báo cho **admin** khi khách đặt đơn mới / cho **user** khi đơn thay đổi trạng thái
- `YeuCauTraHangService` → thông báo yêu cầu trả hàng mới (cho admin)
- Giữ scope nhỏ: 2-3 sự kiện chính, dễ mở rộng sau

## GIAI ĐOẠN 2 — Backend: AskAI Admin Endpoint

### 2.1 `service/AdminAiService.java` (mới)
- `@Service @RequiredArgsConstructor`, inject `OpenAiService`, `ThongKeService`, `ObjectMapper`
- `ask(question, adminUserId)` → **Phân tích câu hỏi tự nhiên**:
  - Trích keyword (doanh thu/đơn hàng/sản phẩm/khách hàng)
  - Query dữ liệu tương ứng qua `ThongKeService` (doanh thu tháng/năm, đơn pending/shipping, top sản phẩm)
  - Build `ArrayNode` messages: system prompt "Bạn là trợ lý AI cho admin ZestStore, trả lời ngắn gọn 2-4 câu dựa trên dữ liệu thực tế" + user question + data context
  - Gọi `openAiService.chat(messages)`, trả về `{ answer, lienKet, data }` (lienKet = gợi ý trang chi tiết)

### 2.2 `controller/AiAnalyticsController.java` (sửa — thêm 1 endpoint)
- Thêm `POST /ask` (body `{ question }`) → `adminAiService.ask(question, userId)`
- Vẫn ở `/api/ai/analytics/ask` với `@PreAuthorize("hasRole('ADMIN")")` đã có

## GIAI ĐOẠN 3 — Frontend: Notifications API + Hook

### 3.1 `src/api/notifications.js` (mới)
```js
getNotifications() → GET /notifications
getUnreadCount() → GET /notifications/unread-count
markAsRead(id) → PUT /notifications/{id}/read
markAllRead() → PUT /notifications/read-all
```

### 3.2 `src/hooks/useNotificationStream.js` (mới — copy `useOrderStream`)
- `EventSource('/api/notifications/stream')`, nghe event `"notification"` + `"connected"`
- Polling fallback: GET `/notifications/unread-count` mỗi 30s nếu SSE fail
- Callback `onNewNotification(payload)` → cập nhật danh sách + badge

## GIAI ĐOẠN 4 — Frontend: NotificationBell + AskAI components

### 4.1 `src/components/admin/NotificationBell.jsx` (mới)
- Icon `Bell` (lucide) + badge bordeaux số chưa đọc (`>99` hiển thị `99+`)
- Dropdown (pattern `useRef` + `mousedown` outside-click giống accountRef trong AdminLayout)
- Mỗi item: tiêu đề, thời gian tương đối ("5 phút trước" — helper `timeAgo`), chấm tròn gold nếu chưa đọc
- Click item → `navigate(lienKet)` + `markAsRead(id)`
- Realtime qua `useNotificationStream` → badge cập nhật tức thì

### 4.2 `src/components/admin/AskAi.jsx` (mới)
- Search bar: input text + icon `Sparkles` bên phải
- Placeholder mặc định "Tìm kiếm...", khi focus/active → "Hỏi AI về doanh thu, đơn hàng, sản phẩm..."
- Submit → `POST /api/ai/analytics/ask` → loading state (gold dots)
- Dropdown kết quả ngay dưới: text trả lời + nút "Xem chi tiết" → `navigate(lienKet)`
- Enter để gửi, Esc để đóng

## GIAI ĐOẠN 6 — Frontend: Refactor AiChat thành Messenger-style

### 6.1 Sửa `src/components/AiChat.jsx` (rebuild UI)
**Trước:** Floating robot head, chỉ hiện 1 tin nhắn AI mới nhất, không có sidebar, không render tin user.

**Sau (Messenger-style):**
- **Panel chính** (khi mở): full chat window `fixed right-0 top-0 h-screen w-[380px]` hoặc modal
  - **Header**: avatar robot + tên "Trợ lý ZestStore" + nút close
  - **Message list scrollable**: render **cả** user bubbles (right, gold) + AI bubbles (left, ivory), auto-scroll `bottomRef`, hiển thị đầy đủ history (bỏ `.slice(-3)`)
  - **Composer**: input + attach (giữ gallery/camera) + send, Enter để gửi
- **Conversation sidebar** (optional, toggle): list conversations + "Cuộc trò chuyện mới" + delete (endpoint có sẵn)
- Giữ nguyên: image upload, product cards, navigation
- Sửa bugs: wire `bottomRef`, bỏ dead state `previewUrl`, bind `onPaste`
